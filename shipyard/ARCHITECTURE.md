## Data pipeline

```
library/registry/{skills.registry,crew,workflows,slots,plugins,tools,artifacts}.json
library/agents/*.md (model, access, routes, phase)        library/doctrines/*/
        └─────────────── python library/tools/project.py shipyard ───────────────┐
                                                                                  ▼
                                     shipyard/public/data/knowledge-base.json  (+ sourceHash)
                                                                                  │ fetch + zod
                                                    src/kb/load.ts → store → screens
ship edits → store → localStorage (convenium.shipyard.v1) │ export → ship.json / 00-run-plan.md / prompt
                                                          │ dev save → shipyard/ships/<id>.ship.json
```

`verify.py` additions (T1): KB is fresh (hash of the sources equals the KB `sourceHash`); every
registry skill resolves to an artifact; every `artifacts.json` override names a registry skill and
contains its family name; every family covers a real category. `project.py all` includes `shipyard`.

## State

One reducer, actions: `ship/create|clone|import|rename|delete|restoreDefault`,
`crew/recruit|edit|dismiss|station`, `loadout/equip|unequip|move|toHold|fromHold`,
`voyage/add|edit|move|delete|applyTemplate`, `codex/inspect`, `log/add`, `ui/introSeen|sound`.
Undo: snapshot stack of 50 per session; every destructive action shows an 8 s undo toast.
Persisted shape `{ version: 1, ships: Ship[], codex: string[], commissions: Record<id, date>, ui }`;
library ships are not persisted (rebuilt from KB), only custom ships and per-ship UI state.

## Dev-only save

`vite.config.ts` registers `POST /__shipyard/save` (dev server only, `apply: 'serve'`): validates
with the same zod schema, writes `shipyard/ships/<id>.ship.json` (id pattern enforced; no path
traversal), returns the path. Production build has no write path.
