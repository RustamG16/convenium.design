## 2026-10-30 — T3 domain (design-engineer, scaffold-domain phase)

- **Measured loadouts (test assertions, not bent):** default ship = 7 crew; the captain derives 12 skills (9 worn, 3 in the hold: `design-analytics`, `visual-qa`, `copywriting`), the engineer 5, the strategist 6. The derivation is stage skills, then agent `routes`, then owned slot defaults, deduplicated, placed by family `autoPlace`, overflow to the hold. It agrees with the plan's numbers.
- **Conversion tables** are authored in `src/domain/conversion.ts` for all four library workflows and checked against the KB on every conversion (every library stage has a row, every KB artifact is produced, every KB crew member has a row, gate and stage order match, skills and crew exist); a gap throws `ConversionError` naming it, and `libraryShips()` returns it under `unconverted` instead of dropping the ship. Stage phase and gate labels are read from the KB, not the table.
- **Deviation carried over (06 §9.1):** `07-qa.md` goes to the builder, `10-finish-review.md` to the critic. Applied by the same method to SS Abridged and SS Mobile Retrofit, whose `verify` stage lists only the critic in `workflows.json`. If the owner prefers the registry's reading, change the tables.
- **Judgement calls in the tables:** retrofit `measure` is run by the `analyst` (as `workflows.json` says) opening `mobile-app-shell` (the retrofit prompt loads it at audit); that is a build-phase skill on a read-only agent, so PF-14 reports it as info (off-route), and PF-14 deliberately ignores the equip-time "read-only agent" warning because PF-07 judges that per stage. Fleet `measure` is the `gauge` (fleet-measurer, stand-in body, station 8). The fleet stage is `parallel: true, wave: 1`.
- **Plan defect found by a negative test (PF-10):** as written ("a verify stage by an agent that built nothing precedes Gate C") the metrics stage satisfied it, so a builder reviewing their own work passed. Tightened: the verify stage must be the independent critic and the critic must have built nothing here. All four library ships still pass.
- **PF-06 interpretation:** outside a fleet, parallel stages must be read-only and at most two per wave; in a fleet, a wave allows one parallel stage per writing member (a ship stage stands for one site's engineer lane; the ship model has no site list).
- **Off-route is info:** both the phase mismatch and the "not in routes" notes from §5.1 are reported at info severity, so they never make a ship unclean. Default loadouts include derived off-route skills (for example `impeccable` on the captain), so the T9 "first artifact equipped off-route" commission must count the owner's equip actions only, never a derived default.
- **Verify reality check:** `verify.py --plan` only checks sanctioned agents, registry skills, outputs and stop. Pre-flight is therefore stricter than verify (gates, design-system order, finish review, parallel limits). `npm run test:plans` also runs a tampered plan as a control: verify.py exits 1 on it, so CLEAN means something.
- **Store:** added `ship/create`, `ship/clone`, `loadout/equip|unequip|move|toHold|fromHold`; the store gets the KB through `setEnv` once loaded. **Not done:** `crew/recruit|edit|dismiss|station`, `voyage/add|edit|move|delete|applyTemplate`, `ship/restoreDefault` (they belong with the Bridge and Voyage screens, T6 and T8).
- **Blank ship:** the schema requires at least one stage and pre-flight needs a design-director, so a blank ship is the captain plus one `run-plan` stage. Library ship timestamps are a constant (`LIBRARY_EPOCH`); they are never shown.
- **Hangar:** now builds the default ship through the domain and shows the hull-integrity ring (14 of 14 for SS Full Run, Verified) and the next goal.
- **Ethics gate in code:** `tests/unit/ethics.test.ts` fails on xp, level(s), streak, ranking/leaderboard, countdown/timer, loot or any random call anywhere in `src/`.
